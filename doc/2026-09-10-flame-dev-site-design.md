# Flame Dev — сайт-визитка. Дизайн-спека (код без макетов)

Дата: 2026-09-10. Основание: `doc/flame-dev-spec.md` (ТЗ), вайрфрейм
Figma `aeSryItOTNYW6bQM6dx7IX` (страница Wireframe, десктоп `1:2`,
мобайл `21:2`), презентация «MW Team — Projects showcase», репозиторий
`FlameAi/landingv2` как источник бренда Flame AI, конвенции из vault
`LLM Dev Setup` (Next.js-архетип, fluid rem, плоский BEM, Formik + Yup,
три уровня анимации).

## 1. Цель и границы

Собрать сайт Flame Dev в коде прямо по вайрфрейму и этой спеке, без
промежуточных макетов в Figma. Сайт должен читаться как часть семьи
Flame (тёмная база, TTFirsNeue, радиусы, свечение), но с синим акцентом
вместо красного. Дизайн-решения принимаются в браузере на живой вёрстке.

В первую версию входит: десктоп 1440 и мобайл 390, все секции 00–08,
преследующий CTA (шапка, плавающая кнопка с мини-формой, липкая панель
на мобайле), форма заявки, ленивые видео с постерами, живые фрагменты в
услугах, pinned-скролл процесса.

Не входит: EN-версия (закладываем структуру текстов, но не роутинг),
финальные тексты и цифры, реальные видеобаннеры (плейсхолдеры в цветах
брендов), мягкий exit-intent баннер (опционален по ТЗ, откладываем),
аналитика, деплой.

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Тема | Полностью тёмная, как Flame AI и Flame CGI |
| Акцент | Кобальт `#3B78FF`, ховер `#6394FF`, текст на акценте тёмный |
| Логотип | FLAME из фирменного SVG Flame AI + DEV надстрочным блоком в той же угловатой пластике, собирается как React-компонент `Logo` с inline SVG |
| Макеты | Нет. Источник истины: вайрфрейм + эта спека, итерации в браузере |
| Стек | Next.js App Router (актуальная стабильная версия), React, TypeScript, SCSS Modules без Tailwind, `next/font/local` для TTFirsNeue, npm |
| Ширины макетов | Десктоп 1440, мобайл 390. Fluid rem: `html { font-size: 10px }`, до 1440 `10/1440*100vw`, до 768 portrait `10/390*100vw` |
| Типографика | Три размера по ТЗ, без промежуточных |
| Процесс | Простой план superpowers в `doc/`, выполнение по задачам с коммитами |

Живут в `:root` в `app/globals.scss` как CSS custom properties.

| `--color-border` | `#3D3D3E` | все бордеры 1px |
| `--color-border-strong` | `#9D9C9E` | нижняя линия инпутов |
| `--color-text` | `#FCFBFB` | основной текст |
| `--color-text-dim` | `#9D9C9E` | вторичный текст, описания |
| `--color-text-cold` | `#B4BBC4` | подписи под шагами, мелкие строки |
| `--color-action-primary` | `#3B78FF` | кнопка primary, ссылки, активный шаг, заливка таймлайна |
| `--color-action-primary-hover` | `#6394FF` | ховер акцента |
| `--color-on-action` | `#0A0A0A` | текст на акцентной заливке |

Нажатое состояние primary-кнопки: заливка `--color-text`, текст
`--color-action-primary` (инверсия, как в Flame AI).

### 3.2 Размеры (в rem, 1rem = 10px на ширине макета)

| Переменная | Desktop 1440 | Mobile 390 |
|---|---|---|
| `--type-display` | 4.8rem | 3.6rem |
| `--type-title` | 2.4rem | 2.4rem |
| `--type-body` | 1.6rem | 1.6rem |
| `--space-section` | 12rem | 8rem |
| `--space-gutter` | 12rem | 2rem |
| `--space-grid-gap` | 2.4rem | 1.6rem |
| `--size-button` | 4.8rem | 4.8rem |
| `--size-button-hero` | 5.6rem | 5.2rem |
| `--size-header` | 8rem | 6.4rem |

Мобильные значения переопределяются в `:root` одним медиа-запросом
`(max-width: 768px) and (orientation: portrait)`. Внутри компонентов
медиа-запросы только для структурных изменений. Шкала отступов внутри
компонентов: 0.4 / 0.8 / 1.2 / 1.6 / 2.4 / 3.2 / 4.8 / 6.4rem. Контейнер
120rem внутри 144rem.

### 3.3 Текстовые стили (миксины в `styles/_typography.scss`)

| Миксин | Размер | Вес | Трекинг | Интерлиньяж | Примечание |
|---|---|---|---|---|---|
| `text-display` | `--type-display` | 700 | −0.03em | 1.1 | hero курсивный, заголовки секций прямые |
| `text-title` | `--type-title` | 700 | −0.02em | 1.15 | названия карточек, шаги |
| `text-body` | `--type-body` | 400 | 0 | 1.5 | описания, теги, кнопки, навигация |

Шрифт: TTFirsNeue, файлы woff2 копируются из
`FlameAi/landingv2/public/fonts/TTFirsNeue/` (400, 500, 700, 700 italic)
и подключаются через `next/font/local` с переменной `--font`.

### 3.4 Форма

Радиусы: 0.8rem контролы и теги, 1.4rem карточки кейсов и услуг, 1.6rem
стеклянные панели (плавающий CTA), 99.9rem чипы. Бордеры 1px. Тени
только ореол CTA: `0 0 4.4rem var(--color-glow), 0 0.6rem 2rem
rgba(0,0,0,.38)`. Стекло: `--color-surface` 55% + `backdrop-filter:
blur(14px)`. Скрим постеров: `linear-gradient(180deg, rgba(0,0,0,.5) 0%,
transparent 25%, transparent 70%, rgba(0,0,0,.5) 100%)`.

Правила: один компонент на файл, `{Name}Props` без `I`, стрелочные
функции с `export default` внизу, `import styles from
'./X.module.scss'`, плоский BEM в классах (`.caseCard__poster`, без
`&__`), контент в `data/`, а не в JSX, алиас `@/*`.

## 6. Секции

**00 Header.** Высота `--size-header`, sticky, фон `--color-bg` 85% +
blur 20px после скролла.

**01 Hero.** Заголовок display курсив «Сложные системы и спецпроекты
для брендов» в две строки, справа три строки body: `[N] лет`, `[N]
проектов`, «Полный цикл: дизайн · разработка · видео». Ниже `HeroReel`
высотой 62rem: Coca-Cola × Delivery Club раскрыта, Росатом, Flame AI,
Tibia, Amatour свёрнуты. Позади полос радиальное свечение
`--color-glow` с блюром 60px (`PageGlow`, следует за курсором). Высота
hero от контента, не от 100vh. Никаких логотипов клиентов.

**02 Кейсы** (`#cases`). Заголовок display. Две равные колонки, все
карточки одного размера, порядок по значимости: Coca-Cola × Delivery
Club, Росатом, Flame AI, Tibia / Majorpack, Amatour, Purina × VK,
AliExpress × ОК, Majorpack, Фонд «Созидание». Текст лежит на плашке
поверх постера (референс agency.uprock.ru). Без метрик и строки про
Huawei.

**02b CTA-полоса.** Заливка `--color-action-primary` на всю ширину,
высота 16rem, текст title `--color-on-action` «Есть задача? Расскажите,
ответим в течение дня», справа `BaseButton variant="inverse"`.
Единственный сплошной синий блок на странице.

**03 Что мы делаем** (`#services`). Заголовок display, четыре
`ServiceSlide` столбиком, см. «Услуги как колода» ниже. Визуалы: таблица Tibia (строки дозаполняются при
наведении), мини-игра «три в ряд» 6×6 на React-стейте, 3D-объект
Росатома (Three.js, следует за курсором), промпт Flame AI (текст
печатается сам, ниже проявляется кадр).

**04 Один подрядчик вместо трёх.** Три карточки, третья про Flame AI с
бордером акцентом.

**05 Как проходит проект** (`#process`). Заголовок display. Секция
пинится, пять `ProcessStep` листаются горизонтально по скроллу колеса
(GSAP ScrollTrigger, `pin` + `scrub`), таймлайн 0.8rem заливается
акцентом синхронно, активный шаг подсвечивается. На мобайле без пина:
горизонтальный `scroll-snap` с таймлайном, заливка по `scrollLeft`. Под
шагами строка body cold: «Один менеджер на проект, демо каждые две
недели, без сюрпризов по срокам».

**06 Flame — это ещё и.** Две карточки со ссылками на flamecgi.com и
Flame AI.

**07 Расскажите о задаче** (`#contact`). Слева заголовок display, body
dim, три ссылки акцентом (Telegram, почта, PDF). Справа `LeadForm`.

**08 Footer.** Высота 9.6rem.

**Мобайл 390.** Один столбец, поля 2rem. Hero: display 3.6rem курсив,
три строки body столбиком, полосы как свайп-карусель (одна раскрыта
29×46rem, следующая выглядывает), пять точек, primary-кнопка во всю
ширину. Карусель на `scroll-snap`, без swiper, пока не понадобятся
жесты сложнее свайпа. Кейсы столбиком в порядке значимости, все
карточки во всю ширину, постер 16:9, текст под постером без плашки, чип под названием. Услуги и «почему» столбиком.
`MobileCtaBar` появляется после hero и скрывается на секции 07.

## 8. Форма и данные

`LeadForm` отправляет `POST /api/lead` с `{ name, contact, message?,
source: 'form' | 'floating' | 'mobile-bar' }`. Route handler валидирует
теми же Yup-правилами и пересылает в Telegram через Bot API
(`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` из `.env`); без переменных в
dev просто логирует в консоль и отвечает 200. Ошибка сети показывается
под кнопкой с предложением написать в Telegram напрямую.

## 9. Анимация и производительность

По конвенции «три уровня эскалации»:

- Уровень 1, `useReveal` (IntersectionObserver + CSS): появление секций,
  полосы hero, ховеры карточек, таблица Tibia, промпт Flame AI, мини-игра.
- Уровень 2, GSAP ScrollTrigger: только секция 05 (pin + scrub).
- Уровень 3, vanilla Three.js в классе `RosatomScene`, монтируется через
  `useEffect`, чанк грузится через `next/dynamic` с `ssr: false` только
  когда карточка в вьюпорте. До появления реальной модели — процедурный
  «атом» (сфера + три орбиты).

Видео: `<video muted playsInline loop preload="none" poster>`, `load()`
и `play()` по входу в вьюпорт через `useInView`, `pause()` при выходе.
Лупы 3–6 с, mp4 + webm, единицы мегабайт. `prefers-reduced-motion`
отключает авто-ротацию, pin и автоплей. Никаких библиотек для reveal и
каруселей.

## 10. Критерии готовности

- `npm run build` и `npm run lint` проходят без ошибок.
- На странице ровно три размера шрифта (проверка по computed styles).
- Все цвета и размеры в компонентах через `var(--…)` и rem, без px в
  модулях (кроме 1px бордеров и blur).
- Секции 00–08 собраны на 1440 и 390, между брейкпоинтами масштабируются
  без ломки за счёт fluid rem.
- Преследующий CTA работает: кнопка в шапке всегда видна, плавающий CTA
  появляется после hero и исчезает на секции 07, липкая панель на
  мобайле ведёт себя так же.
- Форма валидируется, отправляется, показывает успех и ошибку.
- Видео не грузятся до входа в вьюпорт, постеры видны сразу.
- Lighthouse Performance на мобайле не ниже 90 с плейсхолдерами.
- Классы в SCSS плоские, контент в `data/`, компоненты именованы по
  конвенции.

  примерно в 1.67 раза шире каждой соседней. Ширина ленты зависит от доступной высоты,
  лента центрируется. Минимальная высота hero — 60rem / 70rem для сохранения
  читаемости в низких окнах; в таких окнах допустима вертикальная прокрутка.
- Кейсы возвращены к иерархии вайрфрейма: 2 крупных, 3 средних, 4 малых.
  Названия, описания и теги под превью; на мобильном один столбец, превью 16:9.
- Секции разделены тонкими линиями и нумерованными подписями.
  Преимущества оформлены открытыми колонками, форма — отдельной тёмной панелью.
- Убрана редакционная пометка из текста Flame AI. Новые зависимости не добавлены.

Видео в `public/videos/` остаются демонстрационными и визуально не соответствуют
названным клиентским проектам. До публикации нужны настоящие материалы кейсов;
эта итерация обновляет оформление, не подтверждает подлинность демонстрационных роликов.

Подписи hero всегда горизонтальные, с фиксированной шириной набора: при ховере
нет поворота, смены подписей, появления с задержкой и переразбивки строк.


### Форматы видео для продакшна

Используем только два стандартных формата:

- Hero: **9:16**, например 1080×1920. Активная полоса показывает полный
  вертикальный кадр; неактивные полосы временно сужаются при взаимодействии.
- Все карточки кейсов (L/M/S, десктоп и мобильный): **16:9**, например
  1920×1080. Отдельные версии под размеры карточек и мобильный экран не нужны.
- Постер имеет ту же пропорцию, что и соответствующее видео.

Нестандартные 4:3 и 16:10 из видеопревью удалены. Существующие демонстрационные
ролики остаются прежними и могут кадрироваться через object-fit: cover;
финальные материалы нужно поставлять в указанных форматах.


## Итерация «уровень референсов» — 2026-09-14

Основание: разбор cuberto.com, redcollar.ru, ronasit.com, surf.dev, doubletapp.ai,
amiga.ru, dviga.marketing (разметка и CSS-бандлы) и скриншоты текущей сборки на
1440×900 и 390×844. Вывод: премиальность референсов держится на четырёх вещах —
масштаб заголовка, кино под заголовком, доказательства статуса, hover-видео в
кейсах. Кастомный курсор, лоадер и smooth-scroll не используем: их нет у четырёх
из семи референсов, а бюджет анимации по конвенции ограничен тремя уровнями.

Выбран подход «типографика и доказательства» без изменения структуры страницы.
Полноэкранный showreel (cuberto) отложен до появления смонтированного ролика;
кейс-на-экран (redcollar) отклонён как противоречащий ТЗ «короткий сайт».

### Типографика

- `--type-display` = 8rem на 1440, 4rem на 390 (четыре сбалансированные строки заголовка hero). Размеров по-прежнему три.
- Display используют: заголовок hero, названия L-карточек кейсов, номера шагов
  процесса, номера в «Один подрядчик», заголовок секции «Расскажите о задаче».
- Заголовки остальных секций (кейсы, услуги, подход, процесс, экосистема) уходят
  на `text-title` в одну строку с нумерованной подписью: подпись `01 / Кейсы` в
  body dim, заголовок title. Приём redcollar: секции тихие, контент громкий.
- M- и S-карточки кейсов остаются на title.

### Hero

- Заголовок на ширину контейнера (max-width 120rem), две строки на 1440, три на 390.
- Под заголовком одна строка body: «Дизайн, разработка и видео в одной команде».
  Список клиентов текстом пробовали и отклонили. Цифры «лет/проектов» не пишем,
  пока нет подтверждённых значений. Логотипов нет (как и раньше).
- Появление hero: заголовок, подзаголовок и лента входят каскадом через
  CSS-keyframes с `animation-delay` 0 / 0.12 / 0.24 s (приём doubletapp).
  `prefers-reduced-motion` отключает.
- Лента и подписи без изменений.

### Кейсы

- `ICase.industry` — строка отрасли (`FMCG · фудтех`), выводится над названием в
  body dim. Метрик и годов нет: непроверенные цифры не публикуем.
- Видео карточек всегда в автоплее по вьюпорту (режим «только при наведении»
  пробовали и отклонили). Постер при наведении масштабируется до 1.04 за 0.6s.
- L-карточки: название display, M и S — title.

### Подход, процесс, экосистема, футер

- «Один подрядчик вместо трёх»: три колонки получают номер `01/02/03` в display
  цветом `--color-border-strong`, как шаги процесса. Featured-карточка без
  градиента: номер акцентом.
- Процесс: номера автоматически вырастают до 8rem; заголовок секции на title.
- Экосистема: карточки 24rem заменяются одной строкой: заголовок title слева,
  справа две ссылки «Flame CGI» и «Flame AI» в title с описанием в body dim.
  Секционный отступ сверху и снизу уменьшается до `--space-heading`.
- Футер: слева логотип, под ним `hello@flame.dev` в title как ссылка;
  справа навигация. Высота от контента.

### Не меняется

Header, CTA-полоса, услуги (уже сильнее референсов), контакт-форма, преследующий CTA,
мобильная карусель hero, зависимости.

### Hero без зависимости от высоты окна (2026-09-14, уточнение)

Правило «hero занимает доступную высоту окна» отменено. Высота hero — от
контента; лента фиксированной высоты `--size-reel`: 62rem на 1440 (активная
полоса 9:16 ≈ 35rem шириной, трек на всю ширину контейнера, свёрнутые полосы делят остаток поровну), 49rem на
390 (карусель 46rem + точки). `--size-hero-min` и `100svh` удалены.

### Без свечения (2026-09-14, уточнение)

Все эффекты свечения убраны как «нейросетевой» штамп: компонент `PageGlow`
(радиальное пятно за курсором), ореол primary-кнопки на ховере, миксин `glow`,
токены `--color-glow` и `--color-glow-strong`. Остаются только стекло шапки и
мобильной панели (`backdrop-filter`) и обычная тень плавающего CTA.

### Без нумерованных подписей (2026-09-14, уточнение)

Паттерн «01 / Кейсы + линия + маленький заголовок» отклонён как штамп.
Заголовки всех секций снова в display, без подписей и линий-разделителей;
`SECTION_LABELS`, миксины `section-head*` и `section-label` удалены.
Ритм между секциями задаётся только отступом `--space-section`.

### Видео всегда в автоплее (2026-09-14, уточнение)

Карточки кейсов играют по вьюпорту без условий. В hero играет только
активная полоса: пять одновременных видео-слоёв под анимацией чипов давали
дрожание колонки стека (композитор собирал 24 к/с видео и 60 к/с анимацию),
с одним слоем прокрутка ровная. Ролики при этом лёгкие (480×854, ~0,75 Мбит/с),
дело не в декодировании. Наведение только зумит кадр. `prefers-reduced-motion` по-прежнему
останавливает всё.

### Шапка не фиксируется (2026-09-14, уточнение)

По образцу agency.uprock.ru: на десктопе шапка статичная, без блюра и
состояния «после скролла», скроллится вместе со страницей. Раскладка в три
колонки: логотип слева, якоря Кейсы · Услуги · Процесс · Контакт по центру,
RU/EN и «Обсудить проект» справа. Линия под шапкой убрана. На мобильном
шапка остаётся sticky (бургер должен быть доступен для закрытия меню), там же
сохраняется `scroll-padding-top`. Постоянный доступ к CTA обеспечивает
плавающая кнопка и мобильная панель, а не шапка.

### Заголовок одной фразой с чипом (2026-09-14, уточнение)

По образцу agency.uprock.ru: hero без подзаголовка, одна фраза «Сложные системы
и спецпроекты для брендов: [дизайн], [разработка] и [видео] в одной команде».
Каждое слово в скобках — отдельный чип-ссылка: заливка `--color-text`, текст
`--color-bg`, радиус `--radius-pill`, inline-block с line-height 1. Ссылки:
дизайн → `#cases`, разработка → `#services`, видео → flamecgi.com. Ховеры на
чистом CSS (миксин `interact`: те же состояния на `:focus-visible` при выборе через Tab): все три чипа увеличиваются до `scale(1.08)`; «дизайн» поворачивается на −3° и получает выделение как в Figma: кобальтовая
рамка, белые угловые хэндлы с синей обводкой, бейдж с реальными размерами пилюли в px (ResizeObserver, `useChipSize`) под нижней гранью; рамка рисуется слоями фона под хэндлами; «разработка» инвертируется
в тёмную консоль, слово прокручивается вверх сквозь стек Django · Go · React · Next.js (список в `chip.stack`) и возвращается, затем в паддингах появляются `{ }`. Финальная «разработка» наследует цвет чипа и меняется вместе с исходным словом при возврате светлого фона. Слова стека рендерятся через CSS `content: attr(data-word)` из пустых спанов, поэтому текст h1 для поисковиков — ровно фраза заголовка; вариант выбран из шести в артефакте, «декодирование» и Cmd+A-выделение отклонены; «видео»
заливается кобальтом, а внутри букв играет нарезка
из семи роликов Flame AI (`public/videos/hero-video-cut.*`, по 1,1 с, 480×270,
суммарно 484 КБ; источник cdn.flameai.studio).
Слово вырезано SVG-маской из контуров TTFirsNeue Medium (`public/masks/hero-video-word.svg`,
viewBox по метрикам hhea, трекинг −0.03em, letter-spacing после последней буквы как в Chrome).
Ролик с `preload="none"`, играет только при наведении или фокусе (`useChipVideo`).
Варианты play+таймлайн, летербокс, REC, плёнка, заливка, хлопушка и флипбук постеров отклонены.
Ограничение ширины заголовка снято: фраза занимает всю ширину контейнера. Заголовок в
display, но с начертанием 500 вместо 700, размер тот же. Данные — массив
`IHeroTitlePart` в `HERO.title`. Каскад входа: заголовок → лента.

### Услуги: липкий слот визуалов и маска-огонёк (2026-09-15)

Референс — блок Services на ronasit.com: текст слева скроллится в потоке, визуал справа
закреплён и сменяется на месте. Сетка 2×2 с `ServiceCard` заменена на четыре `ServiceSlide`.
На десктопе слайд — `display: contents`, его текст и визуал становятся элементами сетки
`.services__list` (5fr / 7fr, ряды `minmax(64rem, auto)`): тексты идут рядами слева
(заголовок title, описание, чипы стека, по центру ряда), а все четыре
визуала занимают один слот `grid-row: 1 / -1` справа, липкий под шапкой, и лежат стопкой.

Смена (`useServicesStack`, GSAP + ScrollTrigger без пина и скраба): триггер на тексте
каждой услуги (`top 55%` → `bottom 45%`), `onEnter`/`onEnterBack` показывают её визуал.
Переход как в референсе, но огонь разгорается: пока текст очередной услуги идёт от 85% до 35%
высоты окна (`ScrollTrigger`, `scrub: true`), её визуал проявляется поверх предыдущего сквозь
SVG `clipPath` в форме огонька из логотипа (`components/sections/Services/flame.ts`: контур
в единицах objectBoundingBox, кривые вынесены из пути `Logo`, низ плоский на y = 1).
Рост задаёт прогресс скролла: `transform` контура от середины нижней кромки, от 18% до 560%
ширины по степенной кривой (по y домножается на отношение сторон рамки). Контур статичный:
живые языки (морф по фазам волны, турбулентный ореол) отложены, код убран, чтобы не держать
мёртвый вес; вернуть можно по истории git. Видимость входящего визуала считается от прогресса,
а не отдельным `set` в начале таймлайна: на нуле он спрятан целиком, иначе при откате назад
оставалась искра у нижней кромки.
Внутри пламени свечение акцентом (`::after`, радиальный градиент от низа, `mix-blend-mode: screen`),
гаснет по `--glow`. Предыдущий визуал стоит на месте и темнеет (brightness 0.25, scale 0.97).
Остановился — рост замер, языки продолжают дышать; назад — гаснет. clip-path ставится GSAP только
на десктопе, на мобиле и при reduced motion SVG не используется.
Отклонены: круглая маска, скрабный пин всей секции с точками, «колода» с наездом снизу
(выглядела как поезд), растворение с размытием (без связи с брендом), быстрый огонёк по таймеру
(нечитаемо, «чёрная вспышка»), шторка с огоньком-кромкой (просто выезжала, без разгорания), CSS-маска с дрожанием по x
(«кто-то трясёт картонку»), морф со случайным сдвигом точек (изломы, «мятая бумажка»), гладкая волна без турбулентности
(«травка», не огонь), турбулентность на самом визуале (плыло содержимое). Живой огонь (морф + ореол с турбулентностью)
собран и отложен решением 2026-09-15: пока статичный контур.
Мобайл и `prefers-reduced-motion`: без sticky и GSAP, слайд столбиком, визуал 28rem над текстом.
Клетка «три в ряд» задаётся снаружи через `--match3-cell` (4.4rem на десктопе).
Бейдж «интерактив» живёт в верхнем поле карточки визуала, не над контентом сцены.

### Без сквозной нумерации (2026-09-15, уточнение)

Номера `01/02/…` убраны везде: полосы hero-ленты, слайды «Что мы делаем», карточки «Один подрядчик
вместо трёх», шаги «Процесса». Один и тот же приём повторялся в четырёх секциях подряд и читался
как штамп. В «Процессе» активный шаг теперь отмечает заголовок: цвет текста и точка-метка перед ним
акцентом; поле `number` из `IProcessStep` и `data/process.ts` удалено. Display остаётся у заголовков
секций, hero и L-карточек кейсов.

### «Что мы делаем»: баг маски и игрушки

Воспроизведено Playwright 2026-09-15 (скрипты в scratchpad сессии): **в Chromium всё
работает** — десктоп, 390 с тапами, reduced motion, прокрутка колесом во время хода. **В
WebKit (Safari) сломано:**

1. Визуалы обрезаны `clip-path: url(#svg-clipPath)`, контур меняется через `transform` на
   лету. Хит-тест WebKit берёт неактуальную геометрию обрезки: когда активен Росатом или
   после возврата к «Спецпроектам», клик проваливается в нижний визуал Tibia. Игрушка
   видна, но не кликается.
2. Активный визуал выбирается порогом `progress ≥ 0.95` в `onUpdate` скраба. В WebKit при
   прокрутке колесом визуал остался `inert` после конца перехода (подтвердить в настоящем Safari).

Исправление (`useServicesStack`, `ServiceSlide.module.scss`):

- Активный слайд — по событиям ScrollTrigger (`onLeave` / `onEnterBack` триггера перехода),
  а не по порогу прогресса.
- Кликабельность задаём явно, а не формой обрезки: у активного визуала `pointer-events: auto`
  и верхний `z-index`, у остальных `pointer-events: none` и `inert`.
- При `p = 1` снимать `clip-path` целиком (`none`), при `p < 1` возвращать.
- Заменить SVG `clipPath` на CSS-маску: огонёк как SVG data-URI в `mask-image` (с
  `-webkit-mask-*`), рост через `mask-size` и `mask-position`. Маска не влияет на
  хит-тест и стабильнее в Safari. Форма та же.
- `ScrollTrigger.refresh()` после загрузки шрифта и чанка Росатома (ResizeObserver на
  `.services__list`): высоты меняются уже после расчёта триггеров.
- Проверка: Playwright на chromium **и webkit** + настоящий Safari на macOS и iOS.

Технические подписи (Django, React…) пока не трогаем: они уже в `data/services.ts` и
`HERO.title[].chip.stack`, в JSX не зашиты. Финальные тексты — со встречи с Мишей.

### Кейсы: бегущие строки с пином (2026-09-16)

На главной вместо сетки — две бегущие строки избранных кейсов (по 8 в каждой,
`CASES_MARQUEE` в `data/cases.ts`): верхняя едет справа налево, нижняя слева
направо. Секция пинится (GSAP ScrollTrigger, scrub), длина пина равна пробегу
самой длинной строки, так что все карточки успевают побывать на экране. Над
строками заголовок, под ними кнопка «Все кейсы» на `/cases` — там полная сетка
из `CaseCard`. На мобильном и при reduced motion пина нет, строки листаются
пальцем со scroll-snap. Карточка строки (`CaseTile`) — постер 16:9 и подпись,
ведёт на страницу кейса; на странице кейса появилась ссылка «Открыть проект» на
живой адрес (`ICase.live`). В данные добавлены 19 проектов из архива
`../legacy` (демо на Railway), постеры — скриншоты живых проектов в `public/cases/`.

Страница `/cases` (2026-09-16): табы-фильтры по типу работ (`CASE_FILTERS`) и три
колонки карточек `CaseTile` с описанием; по скроллу средняя колонка отстаёт, крайние
обгоняют — CSS scroll-driven animation под `@supports`, без JS. Вариант выбран из
20 в артефакте (12 + фильтры из 13).

Вариант блока кейсов «три наклонные строки» (`CasesTilt`, «Наклонные ряды» в меню): строки по
шесть кейсов, поворот −4°, скорости 1 / 0.7 / 0.85, средняя идёт навстречу. Хук
`useCasesMarquee` обобщён на N строк с коэффициентами скорости. Текущие две строки
остаются по умолчанию.

### Основные варианты и переход к кейсам (2026-09-16)

По умолчанию теперь `HeroOverlay` (кадр во весь экран → карточка) и `CasesTilt`
(наклонные строки). Старые варианты для сравнения: «Лента» и «Прямые строки» в меню вариантов.
Между первым экраном и кейсами работает слой `HomeTransition` с десятью
вариантами перехода по скроллу (группа «Переход к кейсам» в меню, хук `useHomeTransition`):
1 шторка, 2 параллакс, 3 кадр в плитку, 4 зум и размытие, 5 ряды собираются,
6 диафрагма, 7 перелистывание, 8 горизонтальный сдвиг, 9 заголовок-мост,
10 цветная волна. Накрывающие варианты (1, 3, 4, 6, 7, 8, 10) продлевают пин hero
на высоту окна (`coverNext`), кейсы заезжают поверх с отрицательным отступом.
Трансформы hero ложатся на обёртку `heroOverlay__body`, а не на секцию под пином.

Переход 3 «кадр в плитку» доработан (2026-09-16): кейсы не едут снизу, а стоят под пином
у верха окна (`leadIn` в `CasesTilt`, пустой участок пина на высоту окна) поверх hero с
продлённым пином; отступ `data-cover-deep` −200svh. За окно перехода первый экран гаснет,
карточка активного кейса летит в плитку с тем же slug (цель по `data-active` фрейма,
пересчёт через MutationObserver), затем проявляются кейсы и плитка накрывает карточку.
Ролики hero на время перелёта ставятся на паузу. Ряды tilt переставлены так, чтобы кейсы
первого экрана были видны в стартовом кадре.

«кадр в плитку» оставлен для сравнения в меню вариантов, но как слишком сложный
