# Flame Dev · первая визуальная итерация

## Изменения

- Компактный первый экран с отдельной карточкой проекта Росатом
- Видео запускается по действию посетителя
- Шесть избранных проектов доступны статичной сеткой
- Услуги и процесс читаются без закрепления прокрутки
- Серый фон дополнен статичным синим контуром пламени
- Основной текст не уменьшается пропорционально ширине окна
- Главная предлагает пошаговый бриф и короткую форму
- Страница `/formats` позволяет сравнить новый бриф и четыре прежних варианта

## Рекомендация по форме

Пошаговый бриф предлагается как основной вариант, короткая форма остается альтернативой

Окончательный выбор остается за владельцем после сравнения, старые варианты сохранены

Бриф собирает тип проекта, задачу, два уточнения, сроки и контакт

Перед отправкой клиент видит и может отредактировать итог

Возврат на предыдущий шаг без изменения исходных ответов сохраняет редактуру итога

При изменении исходных ответов итог собирается заново, чтобы не отправить устаревшие данные

## OpenAI

На сервере подготовлен `/api/brief` через Responses API

Для включения владелец добавляет секрет `OPENAI_API_KEY` и переменную `OPENAI_MODEL` с доступной в его проекте моделью, поддерживающей Responses API и Structured Outputs

Без этих переменных работают обычные уточнения, кнопка редакторской помощи сообщает о недоступности AI

Для AI отправляются задача и ответы по проекту, поля имени и контакта в этот запрос не входят

Запросы используют `store: false`, ограничение размера входных данных и ответа, тайм-аут, проверку структуры результата и защиту от запросов с другого origin

Защита от частых запросов в текущем варианте действует внутри экземпляра Worker, перед открытым массовым запуском нужна общая квота и ограничение расходов в OpenAI

Реальный ответ GPT пока не проверен, ключ владелец добавляет после публикации

Не обещаем цену, автоматическую оценку бюджета или сроки реализации

[Документация OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)

## Доставка

`/api/lead` работает в обычном Next.js и в Sites через один общий серверный обработчик

Для реальных заявок нужны `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`

Без них сервер возвращает ошибку, форма сохраняет ответы и не показывает ложный успех

Перед запуском сбора обращений подтвердить реальные публичные контакты и получателя

## Публикация

Next.js остается основным фреймворком проекта

`npm run build:sites` собирает публичные страницы в отдельном временном каталоге и общий API в совместимый Worker

Каталог разработки и `app/api` на время сборки не переименовываются

Результат находится в `dist/client` и `dist/server/index.js`, идентификатор Sites сохранен в `.openai/hosting.json`

Секреты управляются через Sites, в Git и браузер не попадают

Обычные `npm run dev`, `npm run build` и `npm run start` сохранены

В новых серверных маршрутах нужно явно поддерживать и Next.js, и входной файл `sites/worker.ts`

Страницы с данными во время запроса потребуют пересмотра текущей схемы публикации, сейчас все страницы контентные и генерируются при сборке

## Проверка

- Пройдены шаги брифа в браузере
- Проверено сохранение ручной правки при возврате назад
- Проверено понятное поведение без ключа GPT
- Главная просмотрена на ширине 1440 и 390, горизонтального переполнения нет
- Подробные материалы кейсов остаются отдельным этапом
